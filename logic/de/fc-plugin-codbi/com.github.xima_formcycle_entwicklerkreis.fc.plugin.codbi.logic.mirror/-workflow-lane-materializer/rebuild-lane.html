rebuildLane

fun rebuildLane(userContext: Any?, rewrite: WorkflowLaneMaterializer.RebuildRequest): WorkflowLaneMaterializer.RebuildReport

Strukturdrift-Fallback: löscht und erstellt die gesamte reflektierende Aktionsspur aus dem Quelle, sodass jeder Quellknoten (einschließlich „FC_RETURN_FILE“) immer in der Reflektion vorhanden ist Arbeitsablauf.

Hier geht es um alles oder nichts (Phase 0: Nur In-Place-Mutationen landen mit demselben Auslöser; eingefügte Knoten landen beim nächsten Auslöser), daher behält MirrorNodePlugin eine Markierung „Neuaufbau ausstehend“ bei und kehrt zurück „WIEDERHERSTELLUNG: ausstehend“. Schritte:

  1. Löschen Sie alle RebuildRequest.childrenToReplace rekursiv.

  2. Weisen Sie JEDEM Quellknoten vorab eine neue Ziel-UUID zu (also Intra-Workflow-NODE-UUID-Referenzen). wie „FC_RETURN_FILE.actionUUIDs“ werden aufgelöst, bevor ein Knoten erstellt wird).

  3. Erstellen Sie den Quellbaum als neue „WorkflowNode“ unter RebuildRequest.laneParent mit dem „customParameters“ neu zugeordnet, „parentOrderIndex“ und „WORKFLOW_NODE_API.create“ verbunden.

  4. Markieren Sie die reflektierende Version „workflowInvalid“, damit das Modell neu geladen wird.
