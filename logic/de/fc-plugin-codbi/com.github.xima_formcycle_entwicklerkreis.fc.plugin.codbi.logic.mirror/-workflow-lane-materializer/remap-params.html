remapParams

fun remapParams(userContext: Any?, targetWorkflowVersion: Any?, sourceStatesByUuid: Map<String, String>, sourceStatesExternalAccess: Map<String, Boolean>, nodeUuidMap: Map<String, String>, paramsJson: String, elementRefs: Map<String, String> = emptyMap()): Pair<String, List<String>>

Ordnet die Referenzen von paramsJson von den bereichsbezogenen Entitäten des Quellprojekts dem Ziel neu zu Projekte, in zwei Stufen:

  1. WorkflowState-UUID-Referenzen werden nach NAME aufgelöst: Quelle „uuid“ -> Quellname -> Ziel-UUID (gleicher NAME), über sourceStatesByUuid / targetStatesByName.

  2. Workflow-NODE-UUID-Referenzen (nodeUuidMap, z. B. „FC_RETURN_FILE“. „ActionUUIDs“, die auf einen vorhergehenden dateierzeugenden Knoten verweisen) sind übersetzte Quellknoten-UUIDs -> die UUID des ENTSPRECHENDEN widerspiegelnden Knotens, sodass die umgeschriebene Spur weiterhin in läuft den Workflow widerspiegeln (Vorgang#907).

Referenzen, die auf keiner Seite aufgelöst werden können, werden unverändert mit einer Warnung durchgelassen (die expliziter No-Op-Fallback des Plans). Alle anderen JSON-Daten werden unverändert übernommen.

  1. Element-Referenzen bilden (elementRefs, siehe MirrorFormAccess.mirroredElementReferenceMap) werden erneut auf die gespiegelten Kopien verwiesen: a Parameter, der ein Quellelement anhand seiner technischen ID/Namen benennt (z. B. FC_IMPORT_FORM_VALUE_FROM_XMLs „XML-Quelle“ „{“resource“:{“type“: „UPLOAD“, „identifier“: „“}}`, sein „xpathMapping“-Ziel Felder, „FC_RETURN_FILE“/„FC_EMAIL.attachments“) – und „%field%“-Platzhalter innerhalb von beliebigen string – wird zur ID/Namespace-Namen der Kopie. Ohne dies zeigt der kopierte Knoten weiterhin an einem Feld, das nur im SOURCE-Formular existiert: Der Eigenschaftendialog zeigt ein EMPTY-Element Picker und der Knoten tun zur Ausführungszeit nichts.

(newJson, Warnungen).
