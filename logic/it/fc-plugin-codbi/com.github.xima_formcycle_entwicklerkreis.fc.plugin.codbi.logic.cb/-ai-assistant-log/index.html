AiAssistantLog

object AiAssistantLog

Persiste e carica il registro delle modifiche di ogni inferenza dell'assistente AI CodBi (modulo + flusso di lavoro).

Ogni "Esecuzione" riuscita di AICodBiAssistant registra una riga nella tabella "codbi_ai_assistant_log" contenente il timestamp, la richiesta dell'utente, l'intento classificato, il modello utilizzato e un file strutturato Descrizione JSON delle modifiche applicate:

  • form – { "widgetsCreated": [...], "widgetsRemoved": [...], "classesSet": [...], "setattributi": [...] }. Gli attributi CodBi data-cb-func / data-cb-* sono contrassegnati con kind: "func" / kind: "param" in modo che l'interfaccia utente possa visualizzarli come elementi speciali e apribili che rivelare i parametri CodBi utilizzati da una funzionalità.

  • flusso di lavoro – [ { "name": "...", "nodeType": "FC_EMAIL", "params": {...} }, ... ] dove ciascuno la voce descrive un nodo del flusso di lavoro e i parametri definiti per esso.

Lo schema della tabella è gestito da CodbiEntities tramite "db/changelog/codbi-ai-assistant-log-changelog.xml".

loadLogs

fun loadLogs(emf: EntityManagerFactory?, formKey: String? = null, limit: Int = DEFAULT_LIMIT, username: String? = null): String

Carica i record di inferenza più recenti ordinati dal più recente. Solo quando formKey non è vuoto vengono restituite le voci di quel modulo (utilizzate dalla finestra di dialogo del registro delle modifiche del designer per mostrare il registro del modulo attualmente in fase di modifica). Restituisce una stringa oggetto JSON { "entries": [...], "totals": { "tokensIn", "tokensOut", "costByCurrency": { "<currency>": costo } } }. Ogni voce ha la forma { "id", "ts", "formKey", "prompt", "intent", "modelId", "form": {...}, "flusso di lavoro": [...] }. I totali vengono derivati lato server dai token di input/output sommati per modello × il prezzo configurato per 1.000.000 di token (raggruppati per valuta), quindi il costo totale non dipende dalla somma dei costi per voce archiviati.
