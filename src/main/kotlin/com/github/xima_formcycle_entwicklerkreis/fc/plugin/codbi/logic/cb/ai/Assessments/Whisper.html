Assessment: Whisper.kt

Date: March 14, 2026 | Branch: Designer_Interface | Repository: CodBi-Dev
File: src/main/kotlin/com/github/xima_formcycle_entwicklerkreis/fc/plugin/codbi/logic/cb/ai/Whisper.kt

Overview

Whisper.kt has been substantially refactored into a thinner orchestration class. It now focuses on plugin-property wiring, lifecycle entry points, and delegating server lifecycle and request handling to WhisperServerManager and WhisperRequestHandler.

Strengths

Clear architectural improvement: the class is now primarily a coordinator instead of a full implementation bucket.
Lifecycle flow is easy to follow: initialize, property load, external-mode short-circuit, local startup, shutdown.
Delegation boundaries are meaningful: server startup/runtime concerns and servlet request concerns are separated.
Configuration parsing is centralized in readPluginProperties, which improves readability and reduces duplication.
Static routing state is updated through a single ready callback, which is easier to reason about than scattered assignments.

Weaknesses & Risks

Some global state remains. activeWhisperPort is still static companion state and can be a coupling point if multiple Whisper instances ever coexist in one JVM.
Recommendation: move toward instance-scoped routing or one explicit runtime registry if multi-instance support becomes relevant.
Whisper.kt still owns property-schema knowledge. The class remains the source of truth for config names and validation, so configuration growth can still increase churn here.
Recommendation: consider a dedicated immutable config object or factory once the property surface grows further.
Readiness behavior is delegated but implicit. External mode calls serverManager.setExternalReady(), which is correct, but the lifecycle contract now depends on delegate semantics staying stable.
Recommendation: document the Whisper-to-WhisperServerManager contract explicitly in code comments or tests.
The most brittle parsing risk moved, not disappeared. Response text extraction now lives outside Whisper.kt in WhisperTranscriptionClient, but it still affects end-to-end correctness.
Recommendation: track this as a system-level risk and prefer structured JSON parsing in the client layer.

Priority Recommendations

  1. Introduce an immutable Whisper config object to remove property-schema churn from Whisper.kt.
  2. Document and test the contract between Whisper.kt, WhisperServerManager, and WhisperRequestHandler.
  3. Reduce static routing state over time if multi-instance or more advanced runtime composition is needed.
  4. Track JSON response parsing robustness in the delegate/client layer as a separate follow-up hardening task.
