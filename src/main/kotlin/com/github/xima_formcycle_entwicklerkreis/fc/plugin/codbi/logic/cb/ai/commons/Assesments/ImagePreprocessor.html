Overview

ImagePreprocessor now offers dual-mode thresholding (Otsu + adaptive) and optimized median denoising, making it a stronger OCR preprocessing component than the previous version.

Strengths

Adaptive thresholding support is a major quality improvement for uneven lighting and shadow-heavy captures.
Integral-image implementation provides efficient local-threshold computation.
Median denoising was optimized to use a fixed primitive buffer, reducing per-pixel allocations and GC pressure.
File and in-memory APIs remain consistent and DPI preservation is handled correctly through DpiUtil.

Risks

Adaptive-threshold defaults (block size and C) are fixed; optimal values vary by document type and camera quality.
Recommendation: expose adaptive parameters through config/header options with safe clamped ranges.
Logging still uses Tesseract-branded messages in a shared commons utility.
Recommendation: make logging context-neutral or inject the caller context.

Verdict

This is a meaningful rewrite and algorithmic improvement. The component is now both higher-quality and more performance-aware, with only tuning/configurability gaps left.
