Assessment v2: LlamaProcessManager.kt

Date: March 14, 2026 | Branch: Designer_Interface | Repository: CodBi-Dev
File: src/main/kotlin/com/github/xima_formcycle_entwicklerkreis/fc/plugin/codbi/logic/cb/ai/commons/LlamaProcessManager.kt

Overview

Lifecycle manager for the LLAMA subprocess with startup polling, health verification, stream logging, and controlled shutdown.

Strengths

Health check logic was improved: JSON status parsing now requires explicit status == "ok".
Fallback for non-JSON health bodies preserves compatibility with older plain-text responses.
TOCTOU race is now documented clearly in code, reducing hidden operational assumptions.
Process output collection and shutdown behavior remain pragmatic and production-safe.

Risks

TOCTOU remains inherently unresolved because the target server cannot bind with port 0 discovery in this flow.
Keep this limitation documented in operator docs and increase retry behavior around startup bind failures.
Output reader threads are not joined; rapid restarts can lose final lines.
Optionally add short joins on reader threads after process stop.

Verdict

A materially improved manager. Recent hardening around health semantics and diagnostics closes previous correctness gaps.
