# CodBi Core Components API (Compact)

Compact reference for AI prompts: one sentence per component and parameter.

### GENERIC RULE for all CSS-Selector parameters below
When a parameter below requires a CSS-Selector referencing another form element,
ALWAYS use the target element's properties.name value prefixed with a dot '.' (e.g., '.tfInterviewBis' or '.taAddress').
NEVER use an ID selector (# prefix, e.g., '#xi-tf-interviewbis'), because
element IDs are mangled in repeatable containers; only properties.name-based selectors work reliably
when CodBi searches within the shared parent container.

- AI.OCR: Applicable on an XUpload field to extract and return text/lines from the uploaded images or PDFs via OCR into a SEPARATE text field (an XTextArea). Use it for requests like 'OCR das Dokument', 'extrahiere den Text', 'Auslesen des Belegs' etc.
  - RECEIVER (CRITICAL, all modes): the OCR result is written into the target text field via the CSS class CodBi_AI_OCR_Receiver. You MUST add the class CodBi_AI_OCR_Receiver to the target XTextArea's 'class' property (e.g. class:"CodBi_AI_OCR_Receiver"). Do NOT use any 'data-cb-Receiver' attribute — there is no such attribute; the receiver is selected ONLY by that CSS class.
  - CLASSIC MODE (Mode 'print', the default): a single XUpload with AI.OCR and the target XTextArea that carries class CodBi_AI_OCR_Receiver. When the user uploads a document the OCR text of the whole document is written into that textarea.
  - PATTERN / SUBSTRING EXTRACTION (KEY RULE): when the user asks to extract only CERTAIN words/numbers/lines from the document (e.g. 'alle Wörter, die mit "Aus" beginnen', 'alle Zahlen', 'nur die E-Mail-Adressen'), you MUST set data-cb-pattern on the XUpload with a regex that captures exactly the wanted tokens. Derive the regex from the natural-language term, LANGUAGE-AGNOSTICALLY (do not hardcode language): the term 'beginnt mit X' / 'starts with X' / 'empieza con X' becomes the word-boundary regex \bX\w*\b; a plain word becomes that word; a number pattern becomes \d+(?:[.,]\d+)? etc. For example 'alle Wörter, die mit "Aus" beginnen' => data-cb-pattern="\bAus\w*\b". In the pattern the special chars { } ^ are written as °{ °} ° to avoid markup corruption, e.g. data-cb-pattern="°{2,°}" means {2,}. When the word boundary/cleanup would remove needed content, prefer a capturing group so ONLY group 1 is written out: e.g. data-cb-pattern="Aus(\w+)" extracts the rest of each 'Aus…' word. When Mode='print' with a data-cb-pattern, ONLY the matching substrings are written into the receiver (separated by newlines); without a pattern the whole text is written.
  - VERIFY MODE (Mode 'verify'): the upload checks the document against a condition; data-cb-Mode="verify".
  - EXTRACT-FIELDS MODE (Mode 'extractfields'): multiple named captures in ONE data-cb-pattern; each capturing group must have a name that equals the CSS class of its target field (class CodBi_AI_OCR_Receiver on every output field too). Rarely needed.
  - FieldPattern_: The regex with named capture groups for the extractfields mode (rarely used).
  - Field: In extractfields mode, CSS-Class-Selector of the target field; in the OTHER modes the receiver is chosen by the CodBi_AI_OCR_Receiver CSS class, NOT by Field.

- DQ.Table.View: Displays the result of a Formcycle DataQuery as an injected HTML table and enables exporting it to an Excel file (.xlsx). Applicable on an XContainer/XContainerInvisible.
  - Centered: Whether the content of the table cells is centered. Defaults to true; set to false/0/no to keep cells left-aligned.
  - Columns: a CSV defining the columns to show, each column is 'label;datacolumn;jsonFlag' with an optional fourth entry ';width' (e.g. 'Anrede;Anrede;false,Unternehmen;Unternehmen;true,Nachricht;Nachricht;false;30'). label is the shown header, datacolumn the column name in the DataQuery result, jsonFlag (true/1/yes) marks a JSON column, width (optional) the column width (chars in Excel, px on screen). When the user skips the column definition, Columns may be left FULLY EMPTY (data-cb-columns="") - the table then renders an EMPTY table (no columns) and the user adds the CSV later in the function's CSV editor.
  - CSS: Optional string of one or more (space separated) CSS classes to apply to both the tagged container and the injected table.
  - DataQuery: REQUIRED - the name of the Formcycle DataQuery on the server whose result shall be shown (e.g. 'HolaQuery' or 'INHALT.Altstadtfest_2027').
  - ExcludeColumns: Optional CSV of column names (matched against the column's label or datacolumn) to EXCLUDE from the Excel-export (they remain visible in the table), e.g. 'Nachricht,Wichtige_Hinweise'.
  - ExportButton: The CSS CLASS selector (must start with '.', NEVER an '#id' or a boolean 'true'/'1') of a REAL button that triggers the Excel export. Only a class selector resolves to the actual '<button>' element; an ID selector resolves to the XButtonList wrapper, so no click handler is attached and the export does nothing. When an Excel export is requested, create a DEDICATED export XButtonList with a single NON-navigation button with NO action, give that button the stable class 'CodBi_Table_View_ExportButton', place the XButtonList as a SIBLING of the DQ.Table.View container (NEVER inside its elements array - the table is rendered inside that container), and point this parameter at the class selector e.g. '.CodBi_Table_View_ExportButton'. WHENEVER an Excel export is requested the SAME container MUST carry ALL SIX attributes together (data-cb-func, data-cb-dataquery, data-cb-columns, data-cb-filename, data-cb-sheetname, data-cb-exportbutton) - never only the first three. The stable class goes into the button's `cssclasses` property - there is NO `classNames` property on an XButtonList button, so NEVER write `buttons:[{ "classNames":[...] }]` (it is ignored and the selector matches nothing, so the export never triggers). The XButtonList item must be emitted as a valid top-level item starting `{ "className": "XButtonList"` (a single `{`; a double-brace `{{` prefix corrupts the JSON and makes the item be dropped as an unknown/null className). The button's LABEL must be exactly "Export Excel" and MUST live in the buttons[].value property ("value":"Export Excel") - Formcycle renders buttons[].value as the button's visible text. `title` is a separate optional TOOLTIP and is NEVER the button label: a button emitted as {"name":"exportExcel","title":"Export Excel","value":""} (label in title, empty value) renders an EMPTY button - a FAIL, so value MUST NEVER be empty. Never use 'Senden'/'Absenden'/'Einreichen' as the label (those are send-labels); the export button is NOT a send button. The button's Formcycle 'Aktion' (action) must be 'keine Aktion' (no action) - stored as {"page":"","check":false,...,"optionId":"no action"}. action.optionId is the machine value the designer uses ('no action' == keine Aktion); a missing/wrong optionId renders the button as 'absenden + prüfen' (submit + validate), so always set optionId:'no action'. This no-action export button is the ONLY NON-submit XButtonList button - do NOT apply the submit-button rule to it.
  - FileName: REQUIRED whenever an Excel export is requested - MUST be set to a sensible value (never left at the bare 'Export' default and never omitted). The name of the exported Excel file WITHOUT extension (always .xlsx). Derive from the query name (strip the datasource prefix/extension), e.g. the query 'INHALT.Altstadtfest_2027' -> 'Altstadtfest_2027'.
  - SheetName: REQUIRED whenever an Excel export is requested - MUST be set to a sensible value (never left at 'sheet1' and never omitted). The worksheet name in the exported Excel file; derive from the query name (same readable core as the filename, max ~31 chars), e.g. 'Altstadtfest_2027'.
  - UrlPartToReplace: Optional CSV of URL parts that shall be replaced in every URL rendered as text inside a cell (and in the Excel export). Only applied when UrlPartReplacement is set as well; both CSVs are combined by position (first entry with the first, second with the second, ...).
  - UrlPartReplacement: Optional CSV of replacements for UrlPartToReplace, combined by position. Both must be present together for the replacement to apply; an empty entry removes the corresponding part from the URL.
