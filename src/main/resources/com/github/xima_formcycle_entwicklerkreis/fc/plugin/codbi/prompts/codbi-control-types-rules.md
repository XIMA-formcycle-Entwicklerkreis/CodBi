CONTROL TYPES: Honor the user's choice of input control type (from the request or the USER CLARIFICATION). "Radio-Button" / "radio" → create an XSelect with selectlayout:"radio" (options with text+value). "Checkbox" → a single XCheckbox for a yes/no question, or an XSelect with selectlayout:"checkbox" for a multi-select option list. "Dropdown" / not specified → XSelect without selectlayout (default dropdown). NEVER generate a plain dropdown when the user explicitly chose radio buttons or a checkbox.

CHECKBOX INITIAL STATE: A generated XCheckbox must be UNCHECKED by default. The INITIAL checked state is controlled by the `"checkedvalue"` property (NOT `"value"` — formcycle ignores a `"value"` key on a checkbox): formcycle renders the box CHECKED when `"checkedvalue"` is `"1"` (the formcycle default), and UNCHECKED when `"checkedvalue"` is `""` (empty string). So ALWAYS set `"checkedvalue":""` for an initially-unchecked box. NEVER emit `"checkedvalue":"1"` (which renders the box CHECKED) unless the user EXPLICITLY requested a pre-checked box ("vorausgewählt", "standardmäßig aktiviert", "initially checked", "pre-checked", "standardmäßig angehakt") — in that case set `"checkedvalue":"1"` together with `"value":"1"` to mark the deliberate pre-check.

PANEL ON AN XCONTAINER (collapsible container): when a container (XContainer/XContainerInvisible) shall become a foldable panel, use data-cb-func=html.panel WITH data-cb-generateheader="true" and a NON-EMPTY data-cb-autoheadertitle (a container has NO legend, so the autoheadertitle is the ONLY source of the header text — invent a short, meaningful title in the form's language when the prompt names none). When the prompt does not describe the header's look, also generate restrained header CSS via data-cb-cssheaderunfolded (base look while unfolded), data-cb-cssheaderhover, data-cb-cssheaderactive and a fold indicator data-cb-cssafterheadercontent / data-cb-cssafterheadercontentunfolded — each value a RAW CSS declaration list WITHOUT braces. FOLDED HEADERS: data-cb-cssheaderunfolded applies ONLY while unfolded, so a panel that STARTS folded is unstyled — use data-cb-cssafterheader / data-cb-cssbeforeheader (+ ...content) for the folded state and ALSO emit a state-independent rule via HTML.CSS (an element with data-cb-func="HTML.CSS" and data-cb-css=".CodBi_HTML_Panel_Header { background:#eef2f7; border-radius:6px; padding:10px 14px; font-weight:600; color:#1e293b; cursor:pointer; }") so both states look identical. Keep the container's name/id/elements and ALL its children (never replace or empty it). XFieldSet panels use the CodBi_HTML_Panel_* classes instead.
