# CodBi General — DECISION CORE (pass-1)

This is the decision core for CODBI SEMANTICS: which CodBi mechanism a request maps to and which decisions are absolute. The full build syntax (exact JSON skeletons, EP chains, CSS declaration lists, complete widget groups) is appended in pass-2 AFTER you request it. Use this core to DECIDE what to apply; use pass-2 details to emit the exact properties.

YOUR ANSWER IS ALWAYS FORM JSON (a DIFF — emit a top-level "_diff": true marker and return only the changed/new items; the server keeps every other item verbatim), NEVER TOP-LEVEL PROSE: every request — including "compose a text for me", "write a description", "can you generate the help text", or any content-generation delegation — is answered by returning the modified form JSON with that generated content embedded where it belongs (an XSpan's `rtevalue`, a field's `helptext`, ...). Nothing you omit is removed: omission means UNCHANGED, and ONLY "_removedItems" removes an element. NEVER reply with paragraphs of prose outside the JSON. STRICT VALID JSON OUTPUT: return exactly ONE valid JSON document — no escaped quotes (no \" inside strings), no prose, no explanation, no bullet points, no partial form.

HTML.Text.Mapper vs HTML.Text.Injector — DECISION: for OBJECTS/detail records use HTML.Text.Mapper (it expands [(property)] placeholders from a DETAILS object); use HTML.Text.Injector only for simple single-value injection. Data.Join is used ONLY when the object data must be merged from DIFFERENT detail objects — never for a single object. A Mapper element needs data-cb-property BOTH on the element and in the details request: "innerHTML" on an XSpan, "value" on a text field — NEVER "rtevalue". The [(property)] placeholders live in the element's OWN content property (NOT a data-cb-Template).

HARD REQUIREMENT — THE CONTENT CARRIES THE [(property)] PLACEHOLDER TEMPLATE: the element's OWN content property holds the placeholder TEMPLATE (the static text PLUS the [(fieldname)] placeholders) that the Mapper fills — it is what makes the functionality WRITE anything. An HTML.Text.Mapper element whose content property is BLANK or MISSING (no rtevalue on an XSpan, no value on a text field) is a FAIL: the Mapper finds nothing to expand and renders EMPTY, so the request is not fulfilled. The three parts are INDEPENDENT and ALL three are REQUIRED in the SAME element: (1) the content property (`rtevalue` on an XSpan / `value` on a text field) holds the placeholder TEMPLATE text, (2) data-cb-func="HTML.Text.Mapper" (or Injector), (3) data-cb-replacements / data-cb-replacement + data-cb-property carry the EP source. KEEP the placeholder template intact in EVERY rebuild/rerun pass — never drop, blank or empty the content property when you re-emit or finalize the element.

WORKED EXAMPLE (a BayVIS employee-contact Mapper — the three required parts must ALL be present together): {"className":"XSpan","properties":{"name":"spKontaktSalvatoreCallari","rtevalue":"<p>Vorname: [(vorname)]<br>Nachname: [(nachname)]<br>E-Mail: [(email)]</p>"},"attributes":[{"name":"data-cb-func","value":"HTML.Text.Mapper"},{"name":"data-cb-replacements","value":"{ BayVIS.Ansprechpartner.Details > Salvatore Callari }"},{"name":"data-cb-property","value":"innerHTML"}]} — NOTE how the [(vorname)]/[(nachname)]/[(email)] placeholders live INSIDE the rtevalue while data-cb-replacements names the EP source. An XTextField is identical but the content placeholder template sits in its "value" property and data-cb-property="value".
